# 字的边缘（锯齿）：测量和修改（2026-11-20）

老机型（legacy，i.MX）用同一套改动；测量在一台 PW6 测试机上做，曲线和抖动的部分与面板无关。i.MX 原来自己的做法
（指数上限 2.5 + 曲线在阈值处拉到白，Oasis 3 用户反馈后加的）在测试页上是 52 %、墨量少 6 %，被邻居规则替换。
测试：tests/legacy-epd（文字页不抖动、图片保留抖动）。

社区问题：“系统选画质、应用跟随，字还是有一点锯齿”。

## 管线

SurfaceFlinger 的 RGBA → `rgba_to_y8*`（亮度 77/151/28）→ `build_lut` 对比度曲线（+ 深色加深、浅色过滤）→ 8 位灰度写进 fb →
FBInk / hwtcon：MDP 把 Y8 转成 Y4（抖动开时用 Y4 抖动，PW6 上 DU 用 Y1 抖动）→ 波形。PW6 / k49 的 Android 是 300 dpi、
1272x1696，和面板一样大，没有缩放（`wm density` / `wm size` 在测试机上查过）。

## 测量（PW6 测试机，EinkBro 打开中英文测试页，fb 原始帧）

fb 里是曲线之后、抖动之前的 8 位灰度；用离线模拟 `build_lut` 得到的结果和真机 fb 逐字节一致，所以曲线的影响可以离线算。
指标：沿行和列，从白（第 15 级）到墨（<= 第 1 级）中间一个灰阶都没有的边缘所占比例（越高越“锯齿”）。

| 设置 | 改之前 | 改之后 |
|---|---|---|
| 对比度 1.0（源） | 16.8 % | 同 |
| 1.3（默认） | 17.1 % | 同 |
| 1.6 / 2.2 | 21.4 % / 27.1 % | 同 |
| 1.3 + 深色加深（指数 2.34） | 28.3 % | 同 |
| 1.3 + 浅色过滤 弱 / 中 | 20.6 % / 27.3 % | 17.1 % / 17.1 % |
| 2.2 + 深色加深 + 浅色过滤 强（测试机上的日常设置） | 75.5 %（只剩 0-6 级 + 白） | 30.4 %（墨量相同） |

浅色底（#EBEBEB / #F5F0E6 / #DCDCDC / #C7EDCC / #C8C8C8）按原来的阈值照样整块变白。

## 改了什么（epd.c）

1. 浅色过滤改成看邻居（`lightf_pass`）：比阈值浅的像素只有四个邻居都不比“阈值 - 24”深时才变白；紧挨笔画的保留曲线值。
   NEON 每次 16 像素：测试机上整屏白 1.5 ms、半屏浅灰底 3.1 ms（纯 C 14–27 ms）；只在浅色过滤开着时跑。
   局部行（P n y0 y1）多转换上下各一行。
2. 深色加深和对比度合起来的指数最多 2.5（对比度本身的上限）。
3. 文字不抖动（`text_no_dither`）：只有含图片的刷新（`img_box`）才带硬件抖动；Y4 抖动会在字边缘撒点，Y1（PW6 的 DU）把整个
   抗锯齿边缘变成点阵。
4. CLEAN 补刷改成 GL16 FULL：PARTIAL 只驱动值变了的像素，DU 之后驱动记的是 Y4 灰度（只有 Y1 抖动才记 1 位），
   同一画面再发 GL16 PARTIAL 什么都不动（`hwtcon_pipeline_config.c:1031`），DU 画成黑白的字边缘一直留着。GL16 不驱动白到白，FULL 不闪。

“画质”档位下的波形：全局 KFB_MODE=3（驱动 AUTO，不抖动）；阅读类应用的内置推荐 KFB_MODE=1（GC16，档位盖不掉它）；
触摸滚动 DU 之后有 REAGL FULL 补刷。所以“画质”里最后停下的画面本来就是 16 级波形，锯齿主要来自曲线和抖动。
